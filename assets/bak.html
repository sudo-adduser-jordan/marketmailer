01 · Pipeline

How it works

Three stages between EVE's market data and the money-making signal on your screen.

01

Poll ESI markets

One manager per SDE region, one worker per ESI page. Every page polls on its own ETag/Expires TTL, so unchanged pages stay cheap 304s, while page 1 reports X-Pages and reconciles the worker set to exactly that many pages.

ESI → per-page ETags → region managers
02

Store locally

Orders land in a single SQLite file (WAL mode) alongside SDE-seeded names, systems, regions and stations. Writes are serialized through one queue, and migrations run automatically on every boot.

SQLite · priv/data/marketmailer.db · auto-migrate
03

Surface the edge

Queries rank remote sell orders that undercut the Jita buy wall, weighted by profit per unit and available volume. Capital hulls that can never enter high sec are filtered out, so every row is actually deliverable. Read it on the console, in Discord, or in the dashboard.

SQL pivot → arbitrage ranked → you
02 · Arsenal

Features

Everything tuned for one job: buying low in the regions and selling high in Jita.

Capsuleer briefing

  • SPREAD SCANNER: A frosted-simple pipeline that finds the single best remote sell order you can instantly flip into Jita's buy wall, ranked by instant_sell_profit.
  • UNDERCUT RADAR: The top-100 items whose remote sell price beats Jita's best buy, ordered by margin — your shopping list for station trading runs across all watched regions.
  • SDE-SEEDED NAMES: Item, system, region and station names are bulk-loaded from the official JSONL SDE by mix sde.import. No ESI round-trips for names; player structures render as Player Station.
  • CAPITAL-FREE BUY WALL: Every Jita query filters out hulls that cannot enter high sec — titans, dreadnoughts, carriers, supers and the rest — so nothing on the list is undeliverable.
  • CONTRACT BOARD: Public contracts are polled and cached too, with item lists fetched once per contract; a 404 on the items drops the contract instead of serving a half-empty row.
  • WATCHDOG INCLUDED: A transport failure halts polling instead of burning error budget, and a DNS+TCP probe resumes every poller the moment the link is back.
  • GLUTEN-FREE CONCURRENCY: A per-region GenServer tree with page scaling and supervisory restarts that survive transient ESI failures.
  • ZERO-DOWNTIME UPGRADES: Castle OTP releases hot-load a patch into the running prod daemon; state-shape changes fall back to a clean restart instead of a half-applied appup.
  • CONTAINS: One SQLite database of market orders, contracts, etags and names, ready to eat — or to query — any time. Perfect for instant arbitrage or a lunch-box trading run.

03 · Launch

Quick start

From clone to a running arbitrage feed — three commands get you there.

cp .example.env .env

Optional. Fill in DISCORD_TOKEN for the bot and any dashboard credentials.

task setup

Deps, migrations, the matching Playwright Chromium, and mix sde.import. The SDE seed creates the region rows the pollers are built from — skip it and no region manager starts.

task start

Build and run the latest tree as a detached prod release daemon. Survives terminal close and is a clean restart every time.

task dev

Interactive shell with the app started — isolated priv/data/dev.db on :4001, safe alongside the prod daemon.

task live:update

Castle hot upgrade in two phases. Refuses on a dirty tree, writes the version bump + appup edge first, and never leaves the daemon down.

task stop

Kill-all switch: gracefully stops the prod daemon, then sweeps orphaned release processes.

mix ecto.migrate

Manual migration control — migrations also run automatically on every boot.

The dashboard lives at :4000/dashboard in prod and localhost:4001/dashboard under task dev; set DASHBOARD_USER + DASHBOARD_PASSWORD to put it behind basic auth.

VariablePurpose
DISCORD_TOKENEnables the optional Discord bot. Missing/invalid → bot skipped with a warning.
MARKETMAILER_DBSQLite file path (default priv/data/marketmailer.db) — e.g. when mounting a Docker volume.
SECRET_KEY_BASESigning secret for the dashboard. Unset → an ephemeral per-boot secret.
DASHBOARD_USER / DASHBOARD_PASSWORDHTTP basic auth for /dashboard when both are set.
DASHBOARD_PORTDashboard port (prod default 4000, task dev default 4001).
DASHBOARD_ENABLEDSet to false to skip the dashboard endpoint entirely.
START_POLLERSDev only — set to false to boot task dev without region pollers.
MARKETMAILER_DEV_DBDev-only database path (default priv/data/dev.db).
04 · Discord

Discord bot

Optional — with no DISCORD_TOKEN the bot is skipped with a warning and the pollers keep running.

/check_market

Best flip for one item: remote sell order against the Jita buy wall, with a Janice chart attached.

/list_market

The ranked undercut board, 10 rows per page with Prev/Next buttons.

/list_contracts

Public contracts at or above a 100m ISK margin, cached from ESI with each contract's item list fetched once.

/database_stats

Order counts, cache sizes, ETag coverage and the running version.

/add_channel

Route a region's broadcast to this channel.

/remove_channel

Stop broadcasting a region here.

/list_channel

Show the current region → channel routing.

Broadcasts wait for one report per polled region, then post the exact /list_market message — so the command and the broadcast can never drift apart. Page 2+ re-queries the database for live data, and Discord expires the buttons 15 minutes after posting.

05 · Internals

Architecture

Fetch → write → read. Pollers only ever write to the SQLite file; every query reads that same file and never touches the network.

Solid arrows are supervision; dashed arrows are runtime links outside it. Poller and dashboard children only boot when enabled, and the ETS caches live outside the tree.
