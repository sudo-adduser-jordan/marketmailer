01 · Pipeline

How it works

Three stages between EVE's market data and the money-making signal on your screen.

1

Poll ESI markets

Per-region pollers fetch market orders from the ESI API with dynamic page scaling and exponential backoff. ETag caching means unchanged regions are skipped in a single request.

ESI → ETag cache → market pollers
2

Store locally

Orders land in a single SQLite file (WAL mode) alongside resolved EVE names for items, systems, regions and stations. Migrations run automatically on every boot.

SQLite · market.db · auto-migrate
3

Surface the edge

Queries rank remote sell orders that undercut the Jita buy wall, weighted by profit per unit and available volume. Readable on the console or in your Discord server.

SQL pivot → arbitrage ranked → you
02 · Arsenal

Features

Everything tuned for one job: buying low in the regions and selling high in Jita.

🍀

Jita spread scanner

Finds the single best remote sell order that can be instantly flipped into Jita's buy wall, ranked by instant_sell_profit — the spread times the volume Jita will actually absorb.

getBestOrder.sql
🌙

Undercut radar

Top-100 items whose remote sell price undercuts Jita's best buy, ordered by margin — your shopping list for station trading runs across all watched regions.

getItemsLessThan.sql
⭐

Lazy EVE name resolution

No static data dumps. Item, system, region and station names resolve on demand from ESI into cached tables, joined straight into query results and re-fetched only when gaps appear.

ESI /universe/names
❤️

Discord bot

Slash commands like /check_market and /list_market, plus scheduled broadcasts to your chosen channel. Optional — without a DISCORD_TOKEN it skips cleanly and the app keeps running.

optional · Nostrum
🌈

Elixir/OTP concurrency

A per-region GenServer tree with dynamic page scaling, an ETS market cache warmed from etags, and supervisory restarts that survive transient ESI failures without missing a beat.

OTP supervisors
🎈

Observability built in

Structured JSON logs on the console and rotated error records in ./logs/errors.jsonl. Every record carries a timestamp and the git commit it was built from — you always know what's running.

ts + commit on every event
03 · Launch

Quick start

From clone to arbitrage feed in three commands.

mix setup

Install deps, create the SQLite database and run migrations.

task start

Run latest tree as prod release daemon (restarts when stale; survives terminal close).

task dev

Interactive shell with the app started — isolated dev.db + :4001, safe alongside prod.

task live:update

Hot-upgrade prod when code changed (patch-bump + appup + release); no-op otherwise.

mix ecto.migrate

Manual migration control (migrations also run automatically on every boot).

VariablePurpose
